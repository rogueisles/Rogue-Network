WHAT REMAINS BEFORE LIVE UPGRADES
1. Freeze permanent production signer identities/services, independent native-data
   access, quorum, difficulty and validity settings into one common configuration.
2. Complete successful real-miner canonical-target V4 block sealing/import and
   owned native-node proposal validation. Earlier V3 mining does not qualify V4.
3. Refresh backups and check all four running nodes' source/build/configuration,
   a common canonical block, and that activation is still safely ahead.
4. Prepare the explorer backend/frontend update so reward display, indexing,
   supply and APR follow the new rules while retaining indexed history.

The corrected local tests and builds are useful evidence, not a guarantee that
a live rollout cannot stall. Missing quorum or mismatched node/pool settings can
stop post-activation mining. The next server steps must be coordinated manually.
No server upgrade, GitHub write or Docker build was performed by packaging.
